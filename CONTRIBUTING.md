# Участие в разработке

> **Pull requests go to `dev`, not `main`.** `main` only takes releases.
>
> **Pull request открывайте в ветку `dev`, не в `main`.** В `main` попадают только релизы.

## Ветки

- Вся разработка идёт в `dev`, это ветка по умолчанию. Ответвляйтесь от свежего `dev` и открывайте
  PR в него же. PR в `main` будет перенаправлен в `dev`.
- `main` меняется только релизным PR `dev → main` и хотфиксами, их делает владелец репозитория.
- Перед открытием PR сделайте rebase на актуальный `dev`, чтобы в PR были только ваши коммиты.
- Крупную фичу или новый коннектор лучше сначала обсудить в issue.

## Перед PR

Окружение описано в README, раздел «Локальная разработка». Те же проверки гоняет CI на каждом PR
(плюс сборка Docker-образа с запуском):

```bash
npm ci
npm run check        # Biome: линт и формат (автоправка: npm run check:fix)
npm run typecheck
npm run build
```

## Правила кода

- TypeScript и только npm: без bun, pnpm и yarn.
- Валидация только на zod, HTTP только через axios: с таймаутом, `AbortSignal` и обработкой ответов
  не-2xx.
- Деньги хранятся в `Decimal`, не в `number`.
- Все строки интерфейса идут через i18n (`apps/frontend/src/i18n/locales/*`), сразу на en и ru.
- Секреты провайдеров хранятся только зашифрованными. Они не попадают ни в логи, ни в ответы API,
  ни в `meta` услуг.

## Новый коннектор

- Код коннектора лежит в `apps/backend/src/connectors/<kind>/`:
  - `<kind>.connector.ts` реализует интерфейс `Connector`;
  - `<kind>.mapper.ts` содержит чистые функции маппинга ответа API в доменную модель;
  - `<kind>.types.ts` описывает только те поля ответа, которые реально используются.
- Если у провайдера есть официальный SDK, используйте его. Если нет, пишите тонкий клиент на axios.
  Используйте только задокументированные эндпоинты.
- Подключите коннектор в нескольких местах:
  - `packages/shared/src/enums.ts`: `providerKindSchema`, а при наличии `fetchPayments` ещё
    `PROVIDER_KINDS_WITH_PAYMENT_IMPORT`;
  - `apps/backend/src/connectors/connector.factory.ts`;
  - форма кредов во фронтенде: `providerForm.ts` и `ProviderCredentialFields.tsx`;
  - название провайдера в `common.ts`;
  - README: список провайдеров и раздел «Провайдеры — где взять доступ».
- Сбой необязательных данных (имя, страна, детали) не должен ронять синк. А вот если не удалось
  получить сам список услуг, синк должен падать: иначе услуги будут помечены неактивными.
- В описании PR напишите, что проверено на живом аккаунте (баланс, услуги, платежи) и какие поля
  API живьём не проверялись.
